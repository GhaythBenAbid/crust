Why it's faster

The request takes half a millisecond. Starting curl takes the rest.

We timed each phase of a small HTTP request. curl's own timers say the network part takes about 0.5 ms. Everything else is the process launching and loading its shared libraries. Homebrew curl links 21 of them.

Where a small HTTP GET spends its time

Milliseconds, mean of 50 runs
Process launch and library loading The HTTP request itself

crust is a single static binary: no shared TLS library to load, no async runtime to start, and TLS is only set up when a URL needs it. The network part is the same speed. The overhead around it is about 3× smaller.

Roadmap

    How it works

    A small pipeline with no wasted steps.

    Each request flows through six stages. The expensive ones only run when a URL needs them.

    01
    Parse flags
    args.rs
    curl syntax: -sSL, -XPOST, -o file
    02
    Expand URLs
    glob.rs
    [1-100] and {a,b} into a list
    03
    Reuse or connect
    http.rs
    Keep-alive pool per host
    04
    TLS, if https
    tls.rs
    rustls + ring, set up lazily
    05
    Parse response
    http.rs
    HTTP/1.1, chunked, redirects
    06
    Stream output
    http.rs
    256 KiB buffer, unbuffered stdout

    No async runtime

    One request at a time needs no event loop. Blocking sockets start instantly and move data just as fast.

    ring for crypto

    We first tried aws-lc-rs and measured 33 ms of crypto startup per HTTPS call. ring brought the handshake down to about 1–2 ms.

    Built to start fast

    Release build with LTO, one codegen unit and panic=abort. The result is a 1.3 MB static binary.

    Install

    Try it next to curl.

    crust is early: keep curl as your default and use crust for everyday requests. You need a Rust toolchain to install it.

    $ cargo install --git https://github.com/GhaythBenAbid/crust
    $ crust -sL https://example.com

    Follow along on GitHub.

    Every benchmark and every test case is in the repo, so you can rerun them on your own machine.
